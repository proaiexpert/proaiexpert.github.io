# Homepage Premium Upgrade Backlog

Status: deferred design backlog.

This document stores external review ideas for the homepage after Header System and Footer System work is complete. These are not approved implementation requirements and must not interrupt current system migration.

## Decision context

The current priority order remains:

1. complete Header System parity and physical migration;
2. complete Footer System migration;
3. return to homepage section upgrades;
4. implement only changes that improve clarity, proof and conversion without adding decorative complexity.

## Candidate 1 — Hero engineering anchor

External suggestion: add an interactive systems diagram or compact working-interface demonstration in the hero.

Assessment: potentially high impact, but only if it communicates a real operating model rather than decorative AI imagery.

Preferred direction:

- restrained system-flow visualization;
- real connection between intake, routing, AI review and next action;
- no generic floating nodes, fake dashboards or unsupported metrics;
- must remain legible and fast on mobile.

Priority: high for later exploration.

## Candidate 2 — Service micro-architecture previews

External suggestion: replace or strengthen text-only service presentation with compact architectural previews.

Potential examples:

- AI Systems: Lead Intake → Router → AI/Rules Layer → Human Review → Team Notification;
- Websites & Branding: responsive page architecture, trust signals, conversion path and inquiry handoff.

Assessment: strong recommendation. It can make the services more concrete and bring the homepage closer to case-study quality.

Constraints:

- diagrams must represent services ProAI Expert can actually deliver;
- no invented production scale;
- mobile version must not become a compressed technical chart;
- each preview needs a clear business outcome, not only tool names.

Priority: high.

## Candidate 3 — Technology environment grouping

External suggestion: group technologies by function, for example:

- Brain & Inference;
- Orchestration;
- Infrastructure & Delivery.

Assessment: directionally useful, but the exact labels and tool list require a fresh audit before implementation. The current Technology Environment has already changed from the older logo-grid version referenced by the review.

Preferred principle:

- communicate system roles rather than display a random collection of brands;
- distinguish currently used tools from capability coverage;
- avoid implying official partnerships;
- preserve the existing premium motion and readability.

Priority: medium-high.

## Candidate 4 — Process deliverables

External suggestion: add concrete deliverables to process phases through hover, expansion or secondary detail.

Assessment: useful, but the review references an older four-phase model. The current homepage workflow contains six stages, so any implementation must use the live workflow architecture.

Preferred direction:

- show one or two credible artifacts per stage;
- support tap and keyboard interaction, not hover only;
- keep the default state concise;
- avoid turning the workflow into a dense project-management checklist.

Potential artifacts:

- process map;
- system flow;
- content architecture;
- UX wireframe;
- implementation checklist;
- launch verification report.

Priority: medium.

## Cross-page quality principle

The strongest useful point from the external review is consistency of visual and informational density. Homepage sections must not look like generic text blocks when case-study pages demonstrate a substantially stronger design standard.

This does not mean every homepage block should become visually complex. The target is consistent quality through:

- stronger proof;
- clearer architecture;
- deliberate spacing;
- useful interaction;
- real implementation detail;
- controlled visual hierarchy.

## Prohibited interpretation

Do not implement the external numeric rating or positioning statements as factual claims. Do not copy phrases such as “digital atelier” or unsupported category leadership into public copy without a separate positioning decision.

## Activation gate

This backlog may be activated only after:

- Header System is approved across laptop, portrait and landscape;
- Footer System is migrated across all four footer families;
- legacy header/footer ownership is removed or explicitly isolated;
- a new homepage audit identifies the highest-return section to improve first.
