5. reusable quality/component standards in their own scopes;

2. Homepage uses concise proof and curiosity, not duplicated case chapters.
3. Service/offer pages use relevant capability proof only.
4. Archive supports comparison and discovery.

`Service or offer → Relevant proof → Case → Relevant contact/offer`

1. Public claims must be tied to current, dated evidence.
2. Impressions are not visits.
3. Search Console snapshots do not prove lead growth, conversion improvement, revenue, SEO ROI, guaranteed rankings or future performance.
4. Historical documents must be explicitly marked and must not appear as current implementation authority.
5. Concept work must never be represented as a completed client engagement.
6. Related-party work must not be presented as independent market validation.
7. Personal images, credentials, documents, testimonials and identifying information require appropriate permission and redaction.
8. Payroll is a confirmed active Financial Stream service and may appear when accurately represented.
9. Preserve public routes, canonical, reciprocal `hreflang`, `x-default`, forms, analytics, integrations, navigation and unrelated content unless a separately verified defect requires change.
10. Do not modify production directly in `main`; use a dedicated branch and reviewable PR.
11. Live visual/network acceptance requires actual verification, not source inspection alone.
12. New outcome evidence requires its own evidence package and approval.
