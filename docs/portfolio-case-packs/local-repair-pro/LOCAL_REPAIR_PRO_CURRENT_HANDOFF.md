## 3. Locked thesis and signature system

### 3.1 Thesis

**From a vague repair need to a request ready for review.**

Natural RU rendering:

**От неясной бытовой задачи — к обращению, готовому к предметному рассмотрению.**

The case is not primarily about designing a handyman homepage. It is about structuring uncertainty before scheduling.

### 3.2 Visitor takeaway

ProAI Expert can turn an imprecise local-service need into a clear, reviewable request through recognizable situations, service grouping, photo context, geographic orientation and structured intake—without fabricated proof.

### 3.3 Signature system

**Photo-to-Scope Field System**

RU public rendering:

**Система «От фото к понятному объёму работ»**

Four steps:

1. `AREA` — общий вид and surrounding context;
2. `DETAIL` — the relevant defect, fixture, finish or access detail;
3. `PRIORITY` — what matters and what result is expected;
4. `FIT` — service group, location, access, materials and specialist boundary review.

The system organizes information for later human review.

It does not:

- recognize or analyze images with AI;
- upload or transmit photographs;
- calculate an estimate;
- generate an automatic scope;
- guarantee project acceptance;
- replace human review.

Visual expression:

- off-white field-sheet surfaces;
- deep-forest rules;
- restrained amber registration marks;
- large readable labels;
- one local alignment effect;
- no permanent grid;
- no dashboard microtype;
- no Financial Stream-style Evidence Reconciliation Register.

2. **Field Note Lock** — Chapters 02–03 and concise source rails; 4 px local registration; 280–320 ms.
3. **Scope Alignment** — Chapter 03 only; one project-specific signature alignment; 4–8 px; 520–580 ms.
4. **Surface Handoff** — confined transitions 01→02, 04→05 and 07→08; 360–420 ms; no page-wide scrub.
5. **CTA Closure** — Chapter 08 only; 440–500 ms desktop; 280–320 ms mobile.

Preferred easing:

`cubic-bezier(0.22, 1, 0.36, 1)`
