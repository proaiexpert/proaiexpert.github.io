## 1. Purpose

This document is the canonical R4.3 target. It consolidates owner direction, independent art-direction review, and external AI review into one implementation and acceptance framework.

The objective is NOT a new Hero concept, a new C-shape, a new layout, or a WebGL rebuild.

The objective is to raise the current R4.x Hero from a good premium static composition / pleasant AI-tech presentation into a bespoke flagship spatial experience with a perceived quality target above the typical $100k agency-site level.

The core diagnostic is:

> The Hero must read as ONE spatial system: information enters, is processed physically inside the Core, changes the material/light environment, and resolves into four meaningful outputs.

It must NOT read as text on the left + a static image on the right + SVG effects drawn over it.

## 6. PASS 2 — Motion Architecture

This is the most important pass.

### A. ENTRY

- Use 2–3 or up to 3–5 short, independent input impulses / seeds / fragments.
- They may enter from slightly different vertical positions.
- They should converge or cohere into a meaningful packet.
- No permanently visible horizontal wire.
- No single-dash-tech-demo look.

Narrative:

> multiple customer/business information inputs → one system.

### B. INGRESS / DEPTH

- Inputs enter the Core.
- Portions of the signal disappear behind actual foreground metal/glass planes.
- Portions reappear deeper inside.
- Brightness, blur, size and speed change by depth.
- Occlusion must be source-aligned with the Core geometry.

Acceptance test:

> A viewer must believe the energy passed BEHIND and THROUGH parts of the object.

### C. PROCESSING

Do NOT use:

- HUD circles;
- radar targets;
- reticles;
- rotating UI rings;
- generic sci-fi dashboards.

Instead:

- sequentially activate internal architectural channels;
- allow a main packet to split briefly into several micro-streams;
- let different depth layers respond in sequence;
- recombine them after processing.

Narrative:

> the Core is not a pipe; it performs intelligence/automation work.

### D. COMPRESSION

- Internal routes converge into one controlled output collector near the natural right-side exit.
- The convergence should feel precise and engineered, not explosive.

### E. DISTRIBUTION

- Collector distributes into four short elegant branches.
- Branch geometry must be clean, restrained, and closely related to the Core output axis.
- Avoid long diagonal connector lines.

### F. RESPONSE

Activation sequence:

1. TRUST
2. INQUIRY
3. RESPONSE
4. OUTCOME

For each stage:

- branch activates;
- node activates;
- number/label rises in luminance;
- local light response appears;
- after activation, previous stages should settle into a quiet resolved/charged state instead of fully disappearing immediately.

### G. IDLE

When no main event is running:

- very subtle inner breathing;
- tiny specular movement;
- soft floor/reflection life;
- no bobbing or floating Core;
- no obvious repeating tech-demo loop.

Preferred overall loop: slow enough to feel cinematic, with meaningful calm time between major sequences.

## 7. PASS 3 — Rail Rebuild

Goal: the right rail must become a physical output architecture, not a list beside an image.

Required:

- Move the rail down approximately 20–30 px from its current R4.2 optical position if needed to align with the natural output axis.
- Test final alignment visually rather than treating the number as absolute.
- Use:
  - collector;
  - short branch;
  - node;
  - number;
  - label.
- Increase breathing room.
- Must be readable in 1–2 seconds.

Idle state:

- branches barely visible;
- nodes small;
- numbers readable;
- labels calm.

Active state:

- branch wakes;
- node lights;
- label increases in contrast;
- state returns softly to baseline/resolved.

Do NOT:

- add long blue/white guides;
- overload with technical UI chrome.

### Optional later rail experiment

A one-line explanatory micro-caption may be tested on hover/focus after the base is approved, e.g. a very short semantic explanation. It is NOT part of P0 because it can overload the Hero and must work on mobile/accessibility.

## 8. PASS 4 — Material / Light / Depth Polish

Goal: remove sterile CGI cleanliness and make light behave as though it exists in the same space as the object.

Add carefully:

- film grain: baseline about 1–2%; exploratory ceiling about 2–3% only if it improves the scene rather than looking like a filter;
- imperfect highlight behavior;
- restrained highlight breakup;
- very subtle chromatic separation only on selected high-energy/highlight edges;
- slow specular movement across 2–3 large graphite planes;
- local cyan bounce from signal onto nearby material;
- local glass/interior illumination response;
- floor response;
- reflection response delayed roughly 80–150 ms relative to the source event where physically appropriate;
- very soft volumetric/haze response around energy events.

Critical principle:

> More physical consequence, not more decorative effects.

### Secondary light note

Keep cyan as the primary accent.

Introduce only a rare warm steel / amber / bronze specular note on metal where it helps material realism.

This is NOT a second UI/brand color.

Do NOT create cyan + orange interface styling.

## 9. PASS 5 — Ambient 2.5D / Parallax Experiments

Grounding is more important than movement.

### Baseline safe experiment

- yaw: approximately 0.35–0.8°
- pitch: approximately 0.2–0.4°
- translation: approximately 1–2 px
- scale breathing: approximately 0.2–0.4%
- long, soft easing

Prefer camera/depth drift over rotating the whole heavy object as one card.

Layer parallax may use different response ratios:

- foreground metal: 1.0×
- glass: ~0.7×
- internal energy: ~0.45×
- floor/reflection: ~0.25×

### Controlled A/B experiments — preserve for later

Do not lose the more aggressive idea; test it only after the safe baseline works.

Possible A/B ladder:

- Variant A: minimal / safe — values above.
- Variant B: medium — roughly 1–1.5° yaw equivalent with slightly larger depth separation if grounding survives.
- Variant C: aggressive exploratory — up to roughly 2–3° only as a comparison proof, never default.
- 3–5° remains a red-zone experiment: only test if the owner explicitly wants to compare it; reject immediately if the Core starts to float, wobble, or feel like an interactive card.

Decision rule:

> Choose the strongest motion that remains invisible as an effect and believable as spatial depth.

## 16. Final Decision Framework

When evaluating any new idea, ask in this order:

1. Does it improve physical causality?
2. Does it improve spatial integration?
3. Does it improve material realism?
4. Does it improve semantic clarity?
5. Does it improve perceived sophistication without demanding attention to itself?

If the answer is only “it looks cool”, it is not enough.

The target is not more animation.

The target is:

> A heavy, grounded, intelligent object living in one cinematic environment, visibly receiving information, processing it through depth, changing light/material around itself, and resolving that information into four controlled business outcomes.
