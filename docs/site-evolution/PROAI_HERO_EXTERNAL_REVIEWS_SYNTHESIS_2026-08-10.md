## 0. Authority and scope

This document synthesizes **all external expert/AI Hero reviews supplied by the owner in the research conversation** after the C-shape R3 direction was frozen.

The current selected architecture is **Hybrid Connected System Core** built from the existing production Hero engineering idea: editorial copy on the left, a central 3D Core, and four DOM-based journey stages.

The archived C-shape is **not** an active option. It remains historical R&D only.

This document is not an implementation task. It is the research synthesis that the next clean execution chat must read before writing the final build specification.

# 1. Strong consensus — KEEP

Across the review corpus, the following points had strong and repeated support.

## 1.1 Core product/story architecture

Preserve the concept:

`ONE CONNECTED SYSTEM`

with a clear journey from first impression / trust through inquiry and response to follow-through / outcome.

The Hero should communicate a business process rather than show a decorative AI object or a feature grid.

## 1.2 DOM + WebGL hybrid

Strong consensus:

### Keep in DOM

- Header and navigation;
- eyebrow;
- H1;
- support copy;
- primary/secondary CTA;
- CTA microcopy/trust line unless later copy review changes them;
- four journey stages and all stage typography;
- accessibility/focus states;
- responsive/mobile layout.

### Use Three.js/WebGL for

- the central 3D System Core;
- geometry/material response;
- internal cyan intelligence/light;
- physically credible reflections/specular/Fresnel behavior;
- camera/light response;
- restrained signal/material state changes;
- contact/grounding cues where useful.

Do **not** put important text inside WebGL.

## 1.3 Editorial left side

The left side should remain calm, readable, expensive and editorial.

Repeated principles:

- H1 is the verbal authority;
- 3D supports the message instead of overpowering it;
- large negative space;
- disciplined typography;
- no generic SaaS density;
- no visual panel split between copy and 3D scene.

## 1.4 One seamless environment

Strong consensus:

- one near-black Hero world;
- no left/right panel seam;
- no separate green rectangle;
- local cyan/blue/warm response only as light/atmosphere from the scene;
- Core and copy must feel composed inside the same environment.

## 1.5 Material family

Strong consensus:

- deep graphite;
- gunmetal;
- cold/dark steel;
- near-black metal;
- limited smoked glass where justified;
- cyan as **internal intelligence/light**, not painted neon;
- physically plausible roughness/specular behavior;
- custom/bespoke material response, not stock Three.js demo styling.

## 1.6 Custom Core geometry

Strong consensus:

Do **not** use a default transparent rotating cube.

The Core must become a bespoke physical object with a clear silhouette and high material credibility.

Repeatedly supported ingredients:

- cube-derived / contained-instrument lineage is acceptable;
- authored bevels/chamfers;
- one or a very small number of inset/aperture operations;
- readable shell thickness;
- restrained internal chamber/intelligence volume;
- no random sci-fi cuts;
- no giant machinery/reactor/server-rack language.

## 1.7 Four stages become a journey, not four equal feature cards

Strong consensus:

- four DOM stages remain useful;
- they must no longer read as parallel service cards;
- one active stage at a time;
- clear inactive/active hierarchy;
- progressive spatial or sequential relationship;
- typography is part of the premium perception;
- avoid four identical glowing square panels.

## 1.8 Motion should explain, not decorate

Strong consensus:

- calm entry;
- premium idle;
- no perpetual spectacle;
- no fast rotation;
- no camera circus;
- no meaningless mouse-follow;
- one readable business story;
- reduced-motion state must be deliberately designed;
- pause work when Hero is offscreen/tab hidden.

## 1.9 Mobile must be redesigned, not scaled

Strong consensus:

- desktop scene must not simply shrink;
- copy first;
- simplified Core identity;
- stages become a deliberate vertical/stacked/sequential mobile journey;
- reduce WebGL complexity;
- remove pointer/gyro gimmicks;
- preserve CTA usability and text hierarchy.

# 3. High-confidence synthesis — Core art direction

The reviews disagree on exact geometry details, but the strongest combined direction is clear.

## 3.1 Recommended Core concept

### Precision-machined contained instrument

A cube-derived, highly readable central volume that feels like an expensive physical product/object rather than a sci-fi prop.

Recommended synthesis:

1. **Simple outer silhouette first.**  
   The object must remain strong in silhouette with all shaders disabled.

2. **One dominant geometry language, not five.**  
   Use restrained chamfer/bevel + one major inset/aperture system. Do not stack bevels + multiple chambers + dozens of cuts + rings + panels.

3. **Functional directional asymmetry.**  
   One of the strongest ideas in the reviews: the form can subtly read more closed/intake-oriented toward the copy side and more resolved/open toward the output side. This can help communicate input → processing → output through geometry itself rather than drawn arrows.

4. **One meaningful smoked-glass aperture / intelligence window.**  
   Prefer one larger controlled window over many little glass panels.

5. **Contained internal intelligence volume.**  
   Internal cyan should feel deep inside the object. Avoid gears, circuit boards, reactor machinery or decorative particle clouds.

## 3.2 Material stack

Recommended hierarchy:

- primary graphite/gunmetal shell;
- satin metal roughness with restrained local variation;
- real bevel highlights;
- one smoked-glass/transmission aperture if it remains performant and visually superior;
- internal cyan emissive/intelligence volume;
- custom studio environment/HDRI or equivalent controlled reflection environment;
- subtle contact/grounding response.

## 3.3 Warm/champagne response — reconcile disagreement

Reviews disagreed whether to remove it entirely or retain it.

Synthesis decision:

**Do not treat champagne/warm silver as a third brand/accent color.**

It may exist only as a very rare physically plausible environmental edge reflection on selected angles. It must not become an obvious designed effect or compete with graphite + cyan.

## 3.4 Pearlescence — reconcile disagreement

Pearlescence is high-risk.

Synthesis:

- not a required feature;
- never rainbow/iridescent RGB;
- if used, it should be microscopic view-dependent material response only after the base graphite/steel material is already premium;
- if it reads as an effect, remove it.

## 3.5 Bloom / glow

Global bloom is rejected.

A tiny selective response on the internal light may be acceptable only if it is visually indistinguishable from physical optical spill. If viewers can identify a post-processing bloom filter, it is too strong.

# 4. Four-stage narrative — consensus and unresolved naming

## 4.1 Structural consensus

Keep a four-stage journey.

The external reviews strongly supported the idea that these stages represent a customer/business path rather than services.

Current baseline:

`TRUST → INQUIRY → RESPONSE → RESULT`

## 4.2 Naming disagreement

There is **no expert consensus** on final stage names.

Proposals included:

- `TRUST → INQUIRY → RESPONSE → RESULT`
- `TRUST → INQUIRY → RESPONSE → FOLLOW-THROUGH`
- `IMPRESSION → INQUIRY → RESPONSE → FOLLOW-THROUGH`
- `FIRST LOOK → REACH OUT → RESPONSE → OUTCOME`
- `FRAME → CAPTURE → CONNECT → DELIVER`
- `PRESENCE → INQUIRY → SYSTEM → IMPACT`

The most repeated critique was that:

- `RESULT` is too generic and does not echo the H1 strongly enough;
- `TRUST` is an outcome of the first impression rather than the first event itself.

### Synthesis recommendation

Do **not** change naming automatically based on external voting.

The next clean chat should run one focused copy/narrative decision against the locked H1 and business truth.

Highest-value candidate to test first:

`TRUST → INQUIRY → RESPONSE → FOLLOW-THROUGH`

because it preserves the already-developed narrative while closing the H1 loop directly.

A more literal alternative to test:

`IMPRESSION → INQUIRY → RESPONSE → FOLLOW-THROUGH`

No other naming system should be introduced unless it clearly beats these two.

## 4.3 Microcopy consensus

External reviews repeatedly rejected vague consultant-style microcopy.

The stage line should be:

- one short sentence or phrase;
- concrete;
- service-business language;
- directly connected to what ProAI Expert actually does;
- small enough to remain premium spatial typography.

Useful recurring concepts:

- first impression / positioning clarity;
- capture useful context/right details;
- connected faster response while human judgment remains;
- less repetitive work / stronger follow-through / more control.

Final exact stage copy remains an **open decision** for the next phase.

# 5. Stage/card visual system — synthesis

There was disagreement between arc, vertical stack, asymmetrical corners and architectural HUD.

There was strong agreement on what **not** to do:

- no symmetric four-corner orbit;
- no equal square cards;
- no generic dashboard grid;
- no identical glowing glass panels.

## Recommended desktop test direction

Use **asymmetrical spatial plates with a directional journey**, not a perfect orbit.

Candidate spatial logic:

- stage 01 near the copy/intake side;
- stage 02 deeper/closer to Core;
- stage 03 on the output side;
- stage 04 in the most resolved/stable position;
- varied but restrained depth;
- one active stage at a time;
- inactive stages remain legible but quiet.

Recommended plate proportions:

- wider than tall;
- editorial rather than dashboard-like;
- strong `01–04` numeral;
- heading + one short line;
- extremely controlled border/material response;
- little or no glassmorphism;
- no icons unless a later test proves they add meaning.

The exact placement — arc vs stepped/asymmetric progression — should be settled with **one static composition prototype**, not by further abstract discussion.

# 6. Input → processing → output — synthesis

This was one of the main disagreements.

External proposals fell into three camps:

1. thin 3D connection traces;
2. no lines, only material/light state change;
3. directional/asymmetric geometry itself communicates the flow.

## Recommended hierarchy

Use the least literal solution that remains understandable.

### Priority 1 — geometry and spatial staging

The Core and stage positions should already imply intake → processing → output in a static frame.

### Priority 2 — internal material/light state

When stages activate, the Core changes internally:

- intake/capture = light becomes receptive/organized;
- processing = internal structure or luminance coheres;
- response = light resolves toward output-facing internal region;
- final state = system settles into one coherent material state.

### Priority 3 — optional transient trace only if needed

If clarity is still insufficient after static geometry + material choreography, allow **one restrained transient hairline trace**. It must never read as a permanent cable, laser or flowchart connector.

Do not start with lines as the primary narrative device.

# 7. Motion synthesis

Reviews disagreed between:

- full four-act synchronized narrative;
- independent slow Core rhythm + card auto-advance;
- one-time autoplay narrative then calm idle/interaction.

## Recommended synthesis

Use a **short one-time narrative sequence followed by calm idle**, combining the strengths of both camps.

### Entry

- copy becomes readable immediately;
- Core materializes through lighting/material definition, not scale explosion;
- stages establish with restrained stagger;
- brief visual pause.

### Narrative pass

- one active stage at a time;
- stage changes are readable, not rushed;
- Core reaction is subtle and causally related;
- no full-object spin for each stage;
- no camera choreography for every beat;
- final stage produces a brief coherent resolution state.

### After first pass

- return to calm idle;
- do **not** immediately loop the full story forever;
- stage hover/focus/tap may preview that stage and corresponding Core state;
- a very infrequent replay may be considered only if it does not compete with reading.

### Idle

- nearly static object;
- extremely slow orientation/material drift;
- tiny internal light modulation;
- pointer parallax maximum approximately 1.5–3° if retained;
- cards remain stable anchors.

### Reduced motion

- complete premium static composition;
- no autoplay journey;
- simple opacity/material state changes on focus/hover only.

### Performance control

- pause rendering/animation when offscreen or hidden;
- adaptive DPR;
- mobile LOD / reduced material complexity;
- no GPU-heavy effect merely because it is available.

# 8. Technical architecture synthesis

## 8.1 Core implementation

Preferred:

- Three.js/WebGL;
- custom modeled Core mesh, ideally built as a real authored asset rather than procedural default cube only;
- MeshPhysicalMaterial / calibrated PBR where appropriate;
- PMREM/environment reflection strategy;
- custom Fresnel/material extension only when visible value is clear;
- restrained transmission for glass aperture;
- internal emissive material/state;
- simple contact shadow/grounding;
- minimal post-processing.

## 8.2 DOM stages

Preferred:

- semantic HTML;
- normal DOM/CSS transforms;
- limited perspective/translateZ where it improves spatial coherence;
- avoid complex CSS preserve-3D systems that distort typography or introduce browser instability.

## 8.3 Orchestration

There was disagreement between one synchronized controller and independent loops.

Synthesis:

Use **one shared state/timeline authority for narrative states**, while allowing low-frequency idle material drift to be independent internally.

The important requirement is deterministic synchronization, not a specific framework.

Avoid adding React/Zustand/other state frameworks unless the existing site architecture actually requires them.

## 8.4 High-ROI technical effects

Prioritize:

1. custom geometry;
2. bevel normals/highlights;
3. environment reflections;
4. calibrated roughness/metalness;
5. internal cyan emissive depth;
6. restrained transmission/smoked glass;
7. Fresnel/specular response;
8. high-quality antialiasing;
9. grounding/contact;
10. performance stability.

Lower priority / generally reject:

- real-time GI;
- ray tracing;
- heavy SSR/SSAO;
- volumetric fog;
- full-scene DOF;
- dense particles;
- complex refraction everywhere;
- chromatic aberration;
- lens distortion;
- expensive post-processing stacks.

# 9. Mobile synthesis

## ~390px portrait

Recommended baseline:

- header;
- eyebrow/H1/support/CTA first;
- compact Core below copy;
- four stages become a vertical or sequential stacked journey;
- stage activation may be scroll-linked or tap/focus-linked;
- no tiny floating desktop cards;
- no pointer/gyro;
- shorter motion;
- reduced Core material complexity.

A sticky Core while journey rows scroll is worth testing, but only if it remains smooth and does not consume too much viewport height.

## ~320px portrait

- simplify Core further;
- preserve silhouette + one key internal cyan identity;
- reduce secondary material subtleties that are not perceivable;
- full-width readable stage rows;
- CTA remains easy to use.

## Short landscape

- compact split layout may remain possible;
- text left / Core right;
- stages collapse to active stage + counter or compact horizontal strip;
- no autoplay spectacle.

# 12. Final synthesis verdict

## KEEP

- Hybrid Connected System Core;
- left editorial communication structure;
- central real 3D Core;
- four DOM journey stages;
- one connected-system narrative;
- near-black seamless environment;
- graphite/gunmetal/cold-steel material language;
- internal restrained cyan;
- DOM + Three.js/WebGL hybrid;
- static-first premium composition;
- meaningful, restrained motion;
- separate mobile recomposition.

## REMOVE

- current demo/neon cube language;
- orbit rings and circular HUD language;
- equal parallel service cards;
- symmetric four-corner composition;
- particle soup/data fields;
- broad bloom;
- holographic/gaming/crypto styling;
- fast/full rotation;
- mouse-follow gimmicks;
- literal diagram arrows/cables/laser lines;
- unnecessary heavy post-processing.

## CHANGE

- Core → bespoke precision-machined contained instrument;
- stages → asymmetrical/sequential spatial plates with one active state;
- static composition → clear intake/Core/output story before motion;
- motion → short first narrative pass, then calm idle + intentional interaction;
- mobile → purpose-built stacked journey;
- signal → primarily geometry + material/light state, optional trace only if clarity requires it.

## ADD

- directional geometry logic;
- strong Core grounding/contact;
- controlled environment/HDRI reflections;
- one meaningful internal aperture/chamber;
- carefully authored stage typography and inactive/active states;
- shared deterministic narrative state;
- performance/reduced-motion/fallback gates;
- static composition gate before detailed motion production.
