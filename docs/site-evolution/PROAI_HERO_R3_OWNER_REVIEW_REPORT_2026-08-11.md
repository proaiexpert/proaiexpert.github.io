## Build decision

R3 keeps the browser-real WebGL2 runtime but replaces the R2 visual composition with a new multi-system procedural architecture rather than preserving the previous geometry. This was chosen over introducing a new external Three.js dependency because the required independent outer, inner, optical, platform and brand systems could be authored directly in the existing zero-asset WebGL2 pipeline while retaining deterministic review states, adaptive resolution and the established fallback/runtime discipline.

The decision criterion was the rendered browser result, not reuse of R2 geometry.

## What R3 deliberately replaces

- R2's smaller, flatter central silhouette;
- weak grounding that was difficult to perceive in screenshots;
- smaller stage plates and conservative active-state lift;
- nearly static-looking Core presentation;
- visually thin internal intelligence;
- sparse signal integration.

## R3 visual architecture

### Outer architecture

A new open engineered Core is assembled from ten authored masses with cube lineage: rear/side sail, crown, keel, right architecture, front plates, diagonal structural shells, rear bridge and an independent output element. The silhouette is intentionally open rather than a closed cube.

### Inner intelligence

The Core contains independently transformed nested frames, suspended dark lamellae/plates, crossed rails and a restrained cyan intelligence kernel. Inner transforms counter the outer motion to make physical parallax and depth legible.

### Optical / signal layer

Multiple asymmetric 3D trajectories, independent signal pulses, DOM/SVG spatial connectors, secondary fragments and nodes create a visible input → Core → output flow without relying on one generic orbital ellipse.

### Materials / light

The shader uses differentiated graphite/gunmetal/smoked/intelligence material classes with moving studio-strip reflections, roughness variation, Fresnel response, AO, soft shadows, cyan edge response and restrained filmic/grain integration.

### Grounding

A two-level low receiver platform, cyan contact response, shadow pool and visible atmospheric halo give the Core physical placement in the scene.

### Brand mark

A small procedural ProAI cube-line mark is integrated into the crown surface and becomes more legible as the object turns through the moving studio response.

## Motion systems

The scene contains several independent physical motion systems:

- slow heavy multi-axis outer architecture rotation/drift;
- different inner counter-motion;
- stage-driven output-element extension;
- independent optical trajectory motion;
- moving signal pulses;
- inertial desktop pointer response;
- autonomous 01 → 04 stage narrative while the Core itself continues moving.

The owner-review motion capture is 30 seconds. Separate same-stage Core-only time probes are also captured so physical geometry/orientation change can be measured without stage-card animation being mistaken for Core motion.

## Stage system

Desktop uses the preferred 2 + 2 spatial journey:

`01 TRUST → 02 INQUIRY → CORE → 03 RESPONSE → 04 RESULT`

RU uses the exact locked equivalent. Plates are DOM controls, materially larger than R2, with graphite/smoked depth, metallic edge cues, cyan active seam/anchor and an active lift around the requested 1.08 scale.
