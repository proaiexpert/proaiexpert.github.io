# Next Implementation Stage

## PROAI REACTIVE ORB — SIGNATURE ADAPTATION R1 — DONOR-FIDELITY FIRST

Это следующий проектный этап после handoff, а не выполненная работа. Перед стартом исполнитель сверяет актуальную базу и действующий процесс/разрешение владельца. Исходной точкой служит сохранённая композиция Reactive Orb, а не Clearance R1/R1.1/R1.2.

## Первая цель

- сохранить исходную композицию;
- сохранить плотность повторяющихся элементов;
- сохранить силуэт Orb;
- сохранить Cloner / локальную реакцию, насколько это подтверждается доступным исходником;
- заменить зелёные/teal материалы;
- заменить демонстрационный свет;
- уточнить камеру;
- уточнить характер движения;
- получить премиальное статическое состояние REST без ввода;
- сравнить оригинал и адаптацию на сопоставимых состояниях.

## Последовательность авторства

**REACTIVE ORB ORIGINAL → PROAI MATERIAL / LIGHTING TRANSFORMATION → MOTION CHARACTER REFINEMENT → AUTHORITY / THRESHOLD BEHAVIOR → SIGNATURE / FORENSIC DETAILS → HERO INTEGRATION**

Сначала установить fidelity исходника и выделить отдельный ProAI-слой. Не выдавать донорскую механику за оригинальное авторство ProAI; сохранять атрибуцию и provenance.

## Явно отложено

На первой адаптационной стадии ещё не реализовывать:

- финальную TRACE / THRESHOLD-семантику;
- крупную authority-геометрию;
- forensic witness;
- финальный provenance asset;
- интеграцию в production Hero.

Эти пункты требуют отдельных решений после оценки адаптации. Данный handoff сам по себе не разрешает изменения production, merge или deploy.

## Cube methodology precedent

Использовать дисциплину ProAI Cube: полезная донорская механика плюс отдельный слой материалов, света, сохранения движения, runtime integration, signature, hidden forensic witness, metadata identity, provenance и QA. См. ссылки в [SOURCE_MANIFEST.json](SOURCE_MANIFEST.json) и записи в репозитории.
