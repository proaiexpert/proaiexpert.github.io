## ROOT CAUSE OF SCALE DIFFERENCE

**Подтверждённое различие:** R2.3 Frame Responsive / Auto Zoom No; R2.5F Responsive / Auto Zoom Yes, Personal Camera zoom 123%, Orb смещён вправо.

Обратимый тест:
1. Auto Zoom No + camera zoom90 + Center In Object дал около 300 px в portrait.
2. На desktop эта же конфигурация также дала около 300 px: фиксированный pixel-size не принят как финал.
3. Возвращён Auto Zoom Yes; zoom увеличен до 180%, камера оставлена центрированной на Clones.
4. Native smartphone и desktop Preview проверены до итогового update; свежий Public Viewer подтвердил 306 px portrait и 705 px desktop.

Причина регрессии кадрирования — **взаимодействие adaptive Auto Zoom и сохранённого Personal Camera framing**, не уменьшение геометрии. Auto Zoom сам по себе не назван дефектом: финальный вариант использует его для desktop/mobile адаптации.

Text/CTA остались hidden, BG Event сохранился с alphaOverride0. Их возможный вклад в вычисление scene bounds отдельно не изолирован. Числовые camera target/position/distance UI не открыл: не выдуманы. Center In Object — штатная camera operation. Camera orthographic; UI предлагает Switch to perspective camera. Показанные FOV45 / Near−100000 / Far100000 не менялись.

## ROOT CAUSE OF RESPONSE DIFFERENCE

Проверка не выявила изменения ключевого Sphere transition относительно R2.3:

- Base: position0/0/0, scale1.39.
- State: position40/−40/0, scale0.10.
- Sphere → Cursor Distance **200**.
- Distance Then: Current → State, **0,50 s / Ease In Out**, delay0, loopNone; Else пуст.
- State Change при входе Sphere в State: State → Base State, **0,50 s / Spring**, delay0, loopNone.
- Cursor Follow: target Cursor, Aligned with camera, XY enabled / Z disabled, damping1, offset0; Hover Out reset, speed5.
- Group State −10/5/10 и Clones Base scale1.05 сохранены.
- Clone249 найден; position133.56/63.06/19.49, scale1; Material A отображается.

Таким образом, доказанные факторы ослабления **восприятия** — scale/framing на mobile и иной material contrast: белые точки оригинала стали гораздо темнее, а Local Depth создаёт похожее затенение каждого bead. Полное равенство всех внутренних transitions не доказано одним наличием узлов; полного видео/пообъектного motion diff нет.

После camera recovery desktop drag показывает локальную область разрежения и пространственную деформацию, затем return; это не только горизонтальная щель. На touch отклик меняет область при разнонаправленном drag.

**Нативные события и states не переписаны**, duration/easing/Distance/Follow не менялись. Нет доказанной причины усиливать их числа вслепую.
