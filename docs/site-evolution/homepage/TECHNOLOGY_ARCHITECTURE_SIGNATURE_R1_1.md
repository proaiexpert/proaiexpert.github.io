## Scope

Locked conceptual sequence:

OPERATING REQUIREMENTS → SYSTEM FIT → TECHNOLOGY ROLES → TOOLS

Locked public thesis:

**The system determines the tools.**

## Why R1.1 exists

R1 established the correct information architecture, semantic model, technology taxonomy, integrity language and interaction logic. Its weakness was art direction: the desktop composition still read as three adjacent information zones, with a relatively small SYSTEM FIT card at the center.

R1.1 changes the visual hierarchy without changing the product logic.

## Selected art direction — Signature Convergence / Architecture Chassis

The section is now built around one integrated machined architecture chassis rather than a requirements column, a center card and a role list.

The chassis contains:

1. one precision incoming spine;
2. four recessed operating-constraint ports;
3. one dominant machined SYSTEM FIT core;
4. four functional technology territories integrated into the same surface;
5. ten platform identities embedded inside those territories;
6. four role paths converging into one implementation/proof output spine.

The intended material vocabulary is obsidian / graphite / dark titanium with restrained pearl edge detail and faint violet interference. Premium depth comes from roughness contrast, edge hierarchy, recessed channels and controlled shadow rather than brighter glow.

No cube is introduced.

## Material changes from R1

### SYSTEM FIT

R1 used a small clipped card. R1.1 replaces it with a large double-layer physical core:

- external machined rim;
- recessed inner face;
- clipped, non-cubic geometry;
- restrained inspection gauge;
- central horizontal authority seam;
- clear VALID CONFIGURATION / SYSTEM FIT hierarchy;
- principle line retained inside the object.

The core is the visual center of gravity and remains recognizable when copy and vendor marks are mentally removed.

### Operating requirements

PROCESS FIT / CONTEXT / CONTROL / INTEGRATION are no longer an ordinary list. They are four recessed constraint ports cut into the chassis surface. Each port has an index, etched label and physical key. Desktop SVG traces feed them into the SYSTEM FIT axis.

### Technology roles and vendors

MODELS / AUTOMATION / COMMUNICATION / BUILD & DELIVERY are no longer independent UI rows. Each is a recessed territory within the same chassis surface.

REST:
- all four territories remain balanced and legible;
- all ten marks remain visible;
- no territory requires interaction to look complete.

ACTIVE:
- selected territory receives a small material/light lift;
- selected typography and marks become authoritative;
- corresponding SVG path gains definition;
- the other three remain visible and are only moderately reduced.

No blur, aggressive glow or large layout shift is used.

## Two Worlds → Technology incoming interface

Technology owns an explicit incoming interface without modifying Two Worlds.

### Required future combined-branch contract

At the Technology section boundary:

- seam centerline: **50% of viewport/section width**;
- seam width: **1 CSS px**;
- terminal key: **17 × 5 px**;
- visual value: pearl/silver at low opacity with restrained violet interference;
- no glow bloom;

Two Worlds should terminate its material fold on the same 50% centerline. Technology takes ownership immediately after the boundary and carries that line behind the chapter thesis into the chassis, where it becomes the SYSTEM FIT spine.

## Technology → Financial Stream outgoing interface

Inside the chassis, the four technology territories converge to a single resolved route. That route bends to the central axis and exits from the bottom of the chassis.

Technology then carries one 1px centerline through its footer/boundary.

Future Financial Stream integration should accept that line as an incoming proof cue, then allow it to disappear into the existing proof composition. Financial Stream content does not need to move to satisfy the contract.

Narrative:

TOOLS → IMPLEMENTATION → PROOF

The owner preview reproduces the expected downstream continuation but does not modify Financial Stream source.

## Motion choreography

One-time sequence:

1. incoming spine establishes;
2. chassis surface is already materially present;
3. four constraints resolve;
4. SYSTEM FIT core becomes authoritative;
5. four role territories resolve;
6. platform identities settle with their territories;
7. convergence/output path resolves;
8. all motion stops.

REST is the designed final state.

Interaction is short and semantic:
- hover/focus temporarily inspects a role when no role is locked;
- click/tap locks/unlocks a role;
- Escape returns to REST.

There is no continuous render loop.

## Accessibility

- semantic h2 and support copy remain real HTML;
- all role controls are native buttons;
- technology names remain real text;
- keyboard focus produces equivalent role authority;
- aria-pressed communicates locked state;
- Escape clears locked state;
- decorative SVG is aria-hidden;
- reduced-motion produces the stable state without staged animation.

## Performance

Explicitly not used:
- Canvas;
- WebGL;
- Three.js;
- runtime texture generation;
- continuous requestAnimationFrame loop;
- particle systems;
- perpetual animation.

Brand assets reuse the existing repository SVG marks.
