## 4. Frozen visual corrections

### 4.1 Register geometry

The five semantic stages must **not** receive equal visual widths.

Do not use full-height separators between CAPTURE / CONTEXT / ROUTE / HUMAN CHECK / ACTION.

Preferred approximate stage anchors at desktop are intentionally asymmetric:

- CAPTURE near 4%;
- CONTEXT near 22%;
- ROUTE near 48%;
- HUMAN CHECK near 73–76%;
- ACTION near 86%.

These anchors are guidance, not a literal table grid.

The Register must read as one continuous precision registration field with 7–9 information strips, different lengths, significant negative space, micro registration marks, and almost square corners.

### 4.2 Human Check physical rule

Preferred construction is now locked:

**INDIGO STOP → VISIBLE VOID → PEARL AUTHORITY THRESHOLD → PERMITTED ACTION**

Required behavior:

- machine/state Indigo terminates before the gate;
- a visible dark void separates machine logic from authority;
- Pearl/Silver introduces permission / human authority;
- Action begins only after the boundary;
- permitted state should not simply resume as the same uninterrupted Indigo line.

Human Check must never appear as:

- fourth equal column;
- button;
- modal;
- approval card;
- lock/shield icon gimmick;
- compliance dashboard.

### 4.3 Hero density

Default desktop density is **5–6 unresolved fragments**, not a filled data field.

Fragments are:

`label + value + registration rule`

not cards.

Preserve large negative space in the right side of the Hero. One incoming line/fragment may clip at the viewport edge.

Hero remains unresolved after its initial settle; it must not reveal the final Register too early.

### 4.4 Pearl Decision chapter

Freeze as an **asymmetric editorial composition**.

Preferred structure:

- dominant statement on the left;
- three vertically weighted decision conditions on the right;
- substantial breathing space;
- no three-card / feature-grid treatment.

Core statement:

EN: `We start with the process, not the AI.`  
RU: `Мы начинаем не с AI, а с процесса.`

Decision order:

1. FIX THE PROCESS
2. AUTOMATE THE RULE
3. USE AI

Pearl is an intellectual pause and semantic authority surface, not decorative light-mode contrast.

### 4.5 Mobile 390

Mobile must be an independently authored vertical sequence:

`RAW INQUIRY → CAPTURE → CONTEXT → ROUTE → HUMAN CHECK → ACTION`

Only one or two states dominate at once.

The Human Check Pearl threshold may and should break the normal 20px mobile gutter to physically interrupt the page.

Do not:

- shrink the desktop Register;
- use five phone mockups;
- create a horizontal swipe rail;
- create a pinned scroll-jacked sequence;
- reduce type to preserve desktop geometry.

## 5. Motion authority

Use two motion characters only.

### Spatial registration

`cubic-bezier(0.16, 1, 0.3, 1)`

### Decision / gate state

`cubic-bezier(0.2, 0, 0, 1)`

Target ranges:

- Hero unresolved settle: 560–620ms
- Diagnostic fragments: 320–420ms
- Operational Register: 980–1040ms
- Capability emphasis: 220–260ms
- Pearl Decision: 450–520ms
- Human Gate: 780–860ms
- Microinteraction: 180–240ms

Motion rule:

> Motion ends immediately after it has communicated state, sequence, or permission.

No idle movement, no breathing glow, no replay on scroll-back, no default blur reveal, no endless rAF loops.

Reduced motion renders the final semantic state immediately.

## 6. Material / color authority

Dark family:

- Obsidian `#020304 / #050607`
- Graphite `#242A31`
- Gunmetal `#2B323A`
- Black Chrome `#181D23`

Authority:

- Pearl `#F2F0EB`
- Silver `#C9CDD1`

Machine state:

- Indigo `#676BFF`
- secondary `#5B50FF`
- subordinate trace `#9BA8FF`

Indigo should normally occupy roughly 2–3% of a viewport, with 5% as a practical ceiling.

Indigo is not a background wash, atmospheric gradient, glow, or universal border color.

Material should be expressed by:

- edge discipline;
- tonal plane differences;
- directional sheen;
- spacing;
- registration marks.

Do not use brushed-metal texture, fake chrome reflections, glassmorphism, cyan atmosphere, or luxury-tech glow.
