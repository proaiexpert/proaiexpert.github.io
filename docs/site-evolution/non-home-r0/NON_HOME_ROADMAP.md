## Roadmap verdict

The proposed phase order is strategically sound and should be kept with one refinement: after the two service pilots, run a short **system consolidation gate** before Contact so shared tokens/components are extracted only after both sibling pages have proven what is truly shared.

Do not start from About or 404 because they are easier. The paired service pages are the correct design-system stress test.

### Required outputs

- EN + RU implementation;

## Phase 1B — Websites & Branding R1 sibling

### Goal

Prove that the inner-site system can support a materially different sibling without cloning the AI page.

### Core build target

`THE AUTHORITY FRAME — STRUCTURE MAKES TRUST LEGIBLE`

### Required difference test

The page must be visibly:

- lighter;
- more editorial;
- more proof/media-led;
- hierarchy/crop-oriented rather than state/sequence-oriented.

If the page can be created by swapping AI copy and colors inside the same layout, **FAIL**.

### Required outputs

Same product/review separation and Owner preview requirements as Phase 1A.

## Phase 1C — Shared-system consolidation gate

This is not a new public page and should stay narrow.

After both service pages are Owner-approved candidates:

1. diff the two implementations;
2. extract only genuinely shared tokens/components;
3. keep page-signature code page-scoped;
4. remove accidental duplication;
5. freeze `Inner Site System R1` before Wave 2.

Do not pre-build an abstract component framework before the sibling pair proves the requirements.

## Phase 2A — Contact

### Why before About

Contact is the conversion endpoint for every redesigned service page. Once the two service pilots are stable, conversion continuity matters more than polishing the trust page first.

### Preserve

- low friction;
- AI / Websites / Both / Not sure routing;
- “no polished brief required” logic;
- direct human contact alternatives;
- clear explanation of what happens next.

### Rebuild

- visual shell;
- form semantics/accessibility;
- mobile composition;
- error/success behavior;
- integration with inner Footer/Header.

### Do not add by default

- AI chat;
- booking-first CTA;
- giant qualifier;
- fake scarcity;
- account creation.

## Phase 2B — About

1. real browser-visible preview;

3. mobile Owner still(s);
4. EN;
