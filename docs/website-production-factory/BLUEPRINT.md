# Website Production Factory Blueprint

## Mission

Create repeatable, premium local-service websites across niches:
- handyman
- construction
- accounting/bookkeeping
- dental/medical clinics
- local services
- professional services

## Operating Pipeline

1. Intake
   - Collect business facts, geography, service scope, proof, contacts, language needs, form destination, and constraints.

2. Niche / Competitor Research
   - Identify competitors, offers, local search patterns, service language, trust signals, and compliance constraints.

3. Sitemap
   - Define homepage, services, service-area hub, city pages, pricing approach, guides, about, request/contact, FAQ.

4. Conversion Strategy
   - Define primary CTA, secondary CTA, request flow, trust architecture, proof limits, and mobile conversion path.

5. Copy Strategy
   - Write conversion-focused, proof-safe copy.
   - Avoid fake reviews, ratings, licenses, warranties, insurance claims, and guaranteed outcomes.

6. Visual Direction
   - Define audience, local tone, imagery style, color system, typography, spacing, and CTA hierarchy.
   - Hero should show the premium outcome or finished result, not defects.

7. Homepage Prototype
   - Build a first complete screen and core conversion sections.
   - Use scenario images when real project proof does not exist.

8. QA
   - Run source QA, rendered desktop QA, rendered mobile QA, link QA, content safety QA, and live/cache QA.

9. Deployment
   - Verify source HEAD, origin/main HEAD, live HTML/CSS, noindex state, and cache-busted URLs.

10. Launch Readiness
   - Confirm claims, service areas, CTA path, forms, mobile behavior, canonical/hreflang where relevant, and final approval.

11. Reusable Template Extraction
   - Extract niche-specific patterns, prompts, page structures, risks, and image rules into factory docs.

## Reuse vs Client-Specific Boundaries

Reuse the factory's structure, QA process, mobile rules, local-service CRO patterns, intake-first strategy, trust architecture, deployment QA, Codex workflow, and task/prompt patterns.

Do not reuse client-specific facts across sites. Business name, service area, photos, reviews, licenses, pricing, phone/email, claims, testimonials, proof, and before/after examples must come from the current client or be labeled as demo/testbed material.

## Strategic Lessons

- Website is a productized system, not a one-off page.
- Each demo should become a niche template.
- A demo site should prove structure, not fake customer proof.
- Local-service websites need clear services, service area, pricing approach, request flow, trust structure, FAQ, and mobile CTA.
