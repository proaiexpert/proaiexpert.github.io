## Изменение C1

Единственный изменённый продуктовый файл: `assets/js/homepage-two-worlds-r5.js`.

`runScroll()` читает текущий scrollY. При изменённом Y вызывает исходный `updateMobile()`, затем ставит следующий RAF, пока мобильная секция подключена, скомпонована и `engaged()`. Один общий RAF-токен исключает параллельные цепочки от scroll-события и sampler. Проверка продолжения использует уже прочитанный Y, без чтения после записей стилей.

Одинаковый Y не вызывает updateMobile/geometry. `IGNORE_SCROLL_PX=2` и исходное условие deadband сохранены. Ни force, ни диагностический обход deadband не используются. Кадр по-прежнему непосредственно зависит от текущего scrollY; интерполяции, нового времени, скорости или сглаживания нет.

Цикл прекращается вне territory, при hidden/pagehide, reduced-motion, desktop-композиции и удалении секции. Возобновление идёт через scroll, compose/pageshow или visibilitychange. Внутри territory при неподвижном scrollY остаётся RAF-сэмплирование без геометрических обновлений — это цена проверки event-gating. Реальный расход батареи iPhone не измерен.

AST-проверка подтвердила неизменность всех функций, кроме runScroll/scheduleScroll и вызовов жизненного цикла sampler в compose. qToP, shapeTurn, geometry, renderMobile, updateMobile, ориентационные расчёты, watermark, CSS и EN/RU includes не менялись.

## Наблюдение и ограничения

Одинаковая preview-телеметрия загружается перед runtime C0/C1. Она не создаёт своего RAF-цикла, не пишет в DOM каждый кадр и не выводит покадровые логи. Считает R5 scroll RAF, scroll-события, fold-transform writes, одинаковый Y, интервалы, события после touchend. Хранит последние 512 образцов в памяти. Кнопка «Метрики» показывает снимок только при нажатии; «Сбросить и закрыть» начинает новую выборку. API: `window.__twR5Cadence.snapshot()` / `.reset()`.

Точные updateMobile/deadband/render-счётчики и ограничение доставки событий добавлялись только в память тестового браузера через Playwright route/initScript. В опубликованных JS/HTML их нет. Контроль с задержанными событиями показывает работоспособность sampler, а не доказывает задержки событий iOS.

Результаты и проверки: [measurement-summary.json](measurement-summary.json). Пройдено 1152 мобильных проверки EN/RU в Chromium/WebKit, 4 desktop-контекста и точная сверка 44 визуальных состояний C0/C1 после штатной перекомпозиции. Chromium и Windows WebKit — эмуляция, не реальный iPhone. Интервалы callback RAF не равны измерению физического вывода кадров. Синтетическая touch-инерция не была достаточно стабильной для вывода о корневой причине. Длинные кадры Windows WebKit нельзя переносить на iPhone GPU.

Сравнительный проход Chromium (portrait / landscape): C0 — 60/60 scroll-событий, 60/60 RAF, 58/58 рендеров; C1 — 60/60 событий, 65/67 RAF, 60/60 рендеров. p95 callback-интервала C0: 36.1/18.3 ms; C1: 18.1/18.2 ms. Это один синтетический проход с trace, а не доказанное ускорение iPhone. Стоимость callback C1 ≤0.5 ms в этом замере; idle внутри секции — 16 RAF, 0 updateMobile, 0 рендеров, ~0.5 ms суммарного JS. Существенная CPU/Paint/Raster-регрессия Chromium не обнаружена; реальный iPhone расход/каденция неизвестны. Искусственное удержание событий: 0 рендеров C0 против 12 C1; 12 шагов по 1 px: 4 рендера у обоих, подтверждая неизменный deadband.
